# 知链学习讲义生成与掌握度评价 v2

模型标识：`zlink-lecture-mastery-v2`

## 1. 讲义生成

讲义请求由中央调度器统一处理，输入包括用户画像、能力证据、知识缺口、学习进度、当前章节与 RAG 检索要求。前端不在接口失败时生成虚假示例内容；每份讲义保存正文、章节、目标维度、学习目标 ID、RAG 来源、知识库版本和生成时间。

## 2. 精确评价关联

过去仅按宽泛能力维度筛选，会让用户做几道无关题后也改变讲义掌握度。v2 只接受同时满足以下条件的证据：

1. `lectureId` 与当前讲义一致；
2. `chapterId` 与当前章节一致；
3. 能力维度属于讲义目标；
4. 证据已通过统一的重复控制和审核规则。

Quiz 设置中提供“用于评估当前讲义”开关。关闭时测验仍保存并更新通用 Memory，但不会改变当前讲义的掌握结论。

## 3. 掌握条件

普通讲义必须同时满足：

- 至少 8 条独立有效评价；
- 至少覆盖 4 个知识点；
- 至少 2 次独立复测；
- 相关题目观察正确率不低于 70%；
- 评价可信度不低于 50%。

涉及安全的讲义还要求安全正确率不低于 80%。涉及操作加工、质量检测或维护诊断的讲义，还必须有至少 1 条已审核实操证据。

没有精确关联证据时显示“待评估”，而不是 0%。证据不足时显示观察表现和可信度，但不输出正式掌握分，也不推荐进入下一阶段。

## 4. 重新生成与下一阶段

- 重新生成会保留旧讲义，并为新讲义建立新的 ID 与评价目标；旧题不能自动证明新版本已掌握。
- 所有条件满足时，可直接生成下阶段讲义。
- 条件未满足时，系统提示继续巩固；用户坚持推进会看到二次确认，且该操作不伪造掌握结论。

讲义历史最多保留最近 50 份，写入后端 SQLite 的 `frontend_state`；浏览器缓存用于后端暂时不可用时的恢复。
